# Portfolio working rules

- Preserve the existing editorial CV visual language unless a task explicitly requests redesign.
- Build and review mobile-first; accessibility and perceived performance are requirements.
- Professional claims must be factual. Never invent clients, responsibilities, metrics, outcomes, or credentials; record missing facts as `UNKNOWN`.
- Do not remove projects, alter deployment, add dependencies, commit, or push without explicit authorization.
- Reuse existing tokens and components before creating new ones. Motion must have a purpose, respect reduced motion, and avoid harming interaction or layout stability.
- Before concluding a change, run the applicable validation in `docs/delivery.md` and report any unavailable checks.
- Use the project skills in `.agents/skills/` when their trigger matches the task.
